# nikkikoole.github.io / mipolai.com

Nikki's personal website: a small **hand-rolled Lua static-site generator**. Write Markdown in
`content/`, run the build, it renders HTML into `docs/`, which **GitHub Pages serves** from the
`docs/` folder on `master` (published at **mipolai.com**).

> This file is orientation + the gotchas that bite. Operational detail lives in `README.md`,
> `PLAN.md` (running decisions/infra record), and `TODO.md`. Read `README.md` first if unsure.

## Layout

```
content/     source Markdown + TOML-ish frontmatter — WHAT YOU EDIT
             sections: about, apps, blog, makes, mipo, stuff, tinyjam (+ top-level content/<slug>.md)
templates/   liluat HTML templates (page shell, head, header/footer, meta tags)
libs/        vendored Lua deps (markdown, toml, liluat, inspect, watcher)
docs/        BUILD OUTPUT — the published site. Regenerated by the build; NEVER hand-edit .html.
             Also holds assets/ (images, fonts). Pages serves this folder.
tools/       optimize-image.sh (the only helper)
main.lua     the build: content/ + templates/ -> docs/*.html + sitemap
run.lua      serve at localhost:8080 + rebuild-on-save
```

## The workflow

1. Edit `content/<section>/<slug>.md`. **New page? Copy frontmatter from an existing page** rather
   than typing fresh — `content/makes/achtbaan.md` is the full pattern (incl. SEO), a blog post is
   the minimal one.
2. **Rebuild `docs/`**: `lua main.lua` (one-shot), or leave `lua run.lua` running (serves + rebuilds
   on save). Preview at http://localhost:8080. Nothing is published until you push.
3. Commit **BOTH** the `content/` change AND the regenerated `docs/*.html`, then push.

### Frontmatter fields

- `timestamp=` unix epoch (`date +%s`) · `date='DD Mon YYYY'` · `title='…'`
- `draft=false` **publishes**; `draft=true` renders the page's own `.html` (reachable by direct URL)
  but keeps it **out of section listings + sitemap** — so a draft shows in git as just its one
  `.html`. Land as draft → eyeball locally → flip to `draft=false` + rebuild → that commit adds the
  listing card + sitemap entry.
- `thumb=` / `score=` / `order=` — listing thumbnail + sort weight.
- `meta=true` + `metaDescription` / `metaImg` / `metaUrl` — SEO/OpenGraph. Verify after a build:
  `grep -iE "<title>|og:|twitter:|canonical|description" docs/<section>/<slug>.html`.
- Body is plain Markdown; raw HTML (`<iframe>`, `<video>`) is allowed.

## Gotchas that bite

- **The stale-site trap:** committing a `content/` edit *without rebuilding `docs/`* publishes the
  OLD HTML. **Always rebuild first, and stage both trees.**
- **Never hand-edit `docs/*.html`** — it's generated and will be overwritten on the next build.
- The build is **idempotent**: git only sees bytes that actually changed. Adding one page touches
  just that page's `.html` (+ listing/sitemap when published). A *big* diff only happens when you
  change a **template or shared chrome** (that legitimately regenerates every page) — not a red flag
  by itself.
- Prereqs on this machine: `lua` at `/opt/homebrew/bin/lua`. Origin is
  `git@github.com:NikkiKoole/nikkikoole.github.io.git`, branch `master`.

## Add an image

```sh
tools/optimize-image.sh <src> <name> [photo|shot] [maxwidth]
```

`photo` (default) → WebP ~900px for real photographs; `shot` → colour-quantized PNG ~1000px for
UI/pixel screenshots (crisp text). Writes into `docs/assets/images/`, prints the exact `![](...)`
line. Never upscales; width is a MAX, not a target.

## Add a looping video (`<video>` pattern)

`optimize-image.sh` is images-only — video + poster go in by hand (see `content/makes/puppetmaker.md`):

```html
<video autoplay loop muted playsinline poster="../assets/images/NAME-poster.webp"
       style="width:640px;max-width:100%"><source src="../assets/images/NAME.mp4" type="video/mp4"></video>
```

Drop the `.mp4` into `docs/assets/images/`; make the poster from a still:
`ffmpeg -i frame.png -c:v libwebp -q:v 80 docs/assets/images/NAME-poster.webp`.

## Showcasing a dreamengine cart (the recurring case)

The common reason this site gets touched: a cart shipped in the **dreamengine** repo
(`/Users/nikkikoole/Projects/dreamengine`) wants a `content/makes/<cart>.md` page. Recipe:

1. In dreamengine, bake a looping clip (`make-gif.js --mp4`) and pull a hero frame
   (`ffmpeg -ss 3 -i clip.mp4 -frames:v 1 frame.png`). No clip? A crisp still via `optimize-image.sh
   … shot` is fine.
2. Copy frontmatter from **`content/makes/acidcandy.md`** — the end-to-end cart reference (shot +
   hero video/poster + full SEO).
3. Land as `draft=true`, drop the `.mp4` + poster into `docs/assets/images/`, rebuild, eyeball.
4. Flip `draft=false`, rebuild, commit both trees, push.

**Draft the copy, but expect Nikki to rewrite it.** A draft is wanted: the page needs words to
react to, and an empty page is harder to start from. It is raw material, not the final voice, so
keep it lean (fewer, shorter paragraphs rewrite more easily than polished ones) and get the FACTS
right — exact key bindings, real preset names, counts read from the source — because those survive
the rewrite even when the sentences don't. Never block shipping a page waiting for copy.

Voice to aim at: short, honest, playful — a stranger should get what the cart *is* and why it's
fun. (dreamengine mirrors this recipe in its `docs/other-projects.md`.)
